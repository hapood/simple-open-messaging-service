# SOMS 核心链路低保真结构方案

状态：Draft v0.1  
依赖：

- [SOMS C 端 UI 改造原则](./consumer-ui-redesign-principles.md)
- [SOMS C 端页面与状态验收矩阵](./consumer-ui-acceptance-matrix.md)
- [SOMS C 端设计 Token 草案与迁移表](./consumer-ui-token-draft.md)

范围：首页、会话列表、聊天头部、消息时间线与输入区

## 1. 目标

本方案定义“打开 App → 找到会话 → 进入聊天 → 发送消息”核心链路的页面结构和响应式行为。
它只确定信息层级、空间关系和交互入口，不规定最终像素级视觉效果。

第一批改造应尽量复用现有 Angular 组件、导航状态机、消息虚拟列表和输入能力，不在视觉改造中
重写稳定的业务内核。

## 2. 核心任务优先级

### 首页

1. 查看未读和最近会话；
2. 搜索已有会话；
3. 开始新会话、添加联系人或创建群聊；
4. 处理好友请求；
5. 进入账户与设置。

### 聊天页

1. 确认正在与谁聊天；
2. 阅读最新消息和发送状态；
3. 输入并发送消息；
4. 发送附件或语音；
5. 搜索消息、发起通话或查看资料。

任何布局档位都必须保证前三项直接可见，其余动作可按空间收纳。

## 3. 响应式模式

| 模式 | 初始建议范围 | 导航结构 | 聊天结构 |
| --- | --- | --- | --- |
| Compact | `<720px` | 单栏首页 | 聊天全屏滑入 |
| Medium | `720–1099px` | 会话栏 + 内容区 | 主从双栏；详情以抽屉覆盖 |
| Expanded | `≥1100px` | 图标导航 + 会话栏 + 内容区 | 主从三栏；详情以侧抽屉覆盖 |

断点值需通过验收矩阵中的代表视口和断点上下实测后确定。

## 4. Compact：首页

### 4.1 默认状态

```text
┌────────────────────────────────────┐
│ 状态栏 / safe area                 │
├────────────────────────────────────┤
│ SOMS                    ＋     头像 │  56px 顶栏
├────────────────────────────────────┤
│ 🔍 搜索会话、联系人                 │  搜索入口
├────────────────────────────────────┤
│ [全部] [未读] [工作] [家人]  →      │  有文件夹时显示
├────────────────────────────────────┤
│ (头像)  林晓                    09:42│
│         明天上午见              2   │
├────────────────────────────────────┤
│ (头像)  设计讨论组            星期六│
│         你：新版已经上传       静音 │
├────────────────────────────────────┤
│ (头像)  Alex @example.org      7月24│
│         [图片]                      │
│                                    │
│             可滚动会话列表          │
│                                    │
└────────────────────────────────────┘
```

顶栏规则：

- 左侧为产品名或当前一级区域名称；
- 右侧固定保留“新建/添加”和账户头像；
- 好友请求角标附着在账户头像，但打开菜单后必须有带文字的“好友请求”条目；
- 不在顶栏同时放置搜索图标和搜索输入框，默认直接显示搜索输入框；
- “新建/添加”打开任务型菜单，不与账户菜单混合。

新建菜单建议顺序：

1. 添加联系人；
2. 发起新聊天；
3. 创建群聊；
4. 扫一扫（平台支持时）。

账户菜单建议顺序：

1. 当前用户摘要；
2. 个人资料；
3. 好友请求及未处理数量；
4. 设置；
5. 主题快捷切换（可选）；
6. 退出登录放在个人资料或菜单底部的危险区域。

### 4.2 搜索激活

```text
┌────────────────────────────────────┐
│ ‹  [搜索会话、联系人          ×]    │
├────────────────────────────────────┤
│ 最近搜索                           │
│  林晓                         ×     │
├────────────────────────────────────┤
│ 会话                               │
│ (头像) 林晓 · 明天上午见            │
├────────────────────────────────────┤
│ 联系人                             │
│ (头像) 林晓然 · 尚未开始聊天         │
└────────────────────────────────────┘
```

第一批实现可以只搜索已有会话，但结构需为后续联系人搜索预留分组能力。

行为：

- 点击搜索框进入专注搜索状态；
- 返回关闭搜索并恢复原列表滚动位置；
- 清除按钮只清空关键词，不直接退出搜索；
- 搜索无结果与账号无会话使用不同空状态；
- 匹配结果可以高亮名称或预览中的命中部分，但不能只依赖颜色；
- 搜索输入使用真实 label/accessible name，placeholder 不是唯一标签。

### 4.3 空会话

```text
┌────────────────────────────────────┐
│ SOMS                    ＋     头像 │
├────────────────────────────────────┤
│ 🔍 搜索会话、联系人                 │
│                                    │
│              [品牌图形]             │
│                                    │
│          开始你的第一段对话          │
│   添加联系人，或创建一个群聊与大家交流│
│                                    │
│          [ 添加联系人 ]             │  主操作
│          创建群聊 · 扫一扫           │  次操作
│                                    │
└────────────────────────────────────┘
```

规则：

- 主操作只能有一个；
- 如果平台不支持扫码则不显示入口，也不留空位；
- 空状态插画或品牌图形不能超过主要文案和 CTA 的视觉权重；
- 加载中不能短暂显示空状态。

### 4.4 加载、失败和离线

| 状态 | 表现 |
| --- | --- |
| 初次加载 | 6–8 行与真实会话结构一致的骨架 |
| 静默刷新 | 保留现有列表，不替换为全屏骨架 |
| 加载失败且无旧数据 | 内容区错误状态 + 重试 |
| 刷新失败但有旧数据 | 保留列表 + 非阻断状态提示 |
| 断网 | 顶部或全局连接状态条；列表仍可查看缓存 |
| 重连成功 | 短暂成功反馈后自动收起 |

## 5. 会话行信息模型

### 5.1 标准行

```text
┌────────────────────────────────────────────┐
│ [头像]  主标题                 时间/发送状态 │
│         草稿/发送者/消息预览     静音  未读数 │
└────────────────────────────────────────────┘
```

信息优先级：

1. 会话身份：头像、名称、群组/联邦标识；
2. 最新消息或草稿；
3. 未读数量与 @我；
4. 时间和发送状态；
5. 静音、置顶等管理状态。

### 5.2 状态规则

| 状态 | 建议表现 |
| --- | --- |
| 未读 | 名称/预览适度加重 + 数字角标 |
| 99+ 未读 | 角标显示 `99+`，宽度增长但不挤压头像 |
| 草稿 | 预览前显示语义化“草稿”，使用危险色或品牌强调需视觉确认 |
| 发送中 | 预览或时间区域显示轻量发送中状态 |
| 发送失败 | 预览前显示错误图标和“发送失败” |
| 静音 | 时间附近显示静音图标，未读角标降低强调但仍可读 |
| 置顶 | 不额外长期显示大图标；通过排序和可选微型标识表达 |
| 当前选中 | 使用 `--app-selected-strong`，与 hover/pressed 明确区分 |
| 联邦用户/群 | 名称后紧凑域名标识，完整域名通过资料或 tooltip 查看 |

### 5.3 交互

- 整行使用原生 button 或具备等价语义；
- Enter/Space 打开会话；
- 桌面 hover 显示状态背景，touch 使用 pressed；
- `focus-visible` 环绕整行且不被列表裁切；
- 桌面右键菜单属于增强能力，不替代更多菜单或详情入口；
- 长按操作若加入移动端，必须避免与列表滚动冲突；
- 打开会话后保留列表滚动位置。

## 6. Compact：聊天

### 6.1 默认结构

```text
┌────────────────────────────────────┐
│ 状态栏 / safe area                 │
├────────────────────────────────────┤
│ ‹  (头像) 林晓              📞  ⋯  │
│           在线/简介/群成员数         │  固定头部
├────────────────────────────────────┤
│             7月26日                │
│                                    │
│  ┌ 收到的消息 ┐                    │
│                    ┌ 发出的消息 ┐   │
│                                    │
│  [图片/文件/语音等消息]             │  可滚动时间线
│                                    │
│                    发送失败  ↻      │
│                                    │
├────────────────────────────────────┤
│ 🙂  输入消息…            ＋     🎤 │  输入区
│ 手势区 / keyboard                  │
└────────────────────────────────────┘
```

头部规则：

- 返回、头像/标题和更多始终可见；
- 语音通话在单聊可用时直接显示；
- 视频通话在空间不足时收纳进更多菜单，避免两个通话图标挤压标题；
- 点击头像/标题整体进入资料，使用一个明确 button，不采用多个隐形 span 点击区；
- 副标题只有存在有价值信息时显示；
- 标题过长时优先保留返回和更多，通话动作可收纳；
- 所有操作使用统一 SVG 图标，不使用系统 emoji。

### 6.2 消息时间线

- 背景使用 `--chat-bg`，壁纸是否保留由视觉确认门决定；
- 内容区与顶栏、输入区物理分离，但不使用多余重阴影；
- incoming/outgoing 使用不同对齐与气泡容器，不只依赖颜色；
- 长消息的正文、时间和状态必须保持可读；
- 同一发送者连续消息通过间距和角点分组；
- 群聊只在需要处显示发送者和头像；
- 时间分隔条和浮动日期使用同一语义；
- 用户位于底部时接收新消息自然跟随；
- 用户阅读历史时显示“回到底部/新消息”浮动入口，不强制跳转。

### 6.3 输入区默认态

```text
┌────────────────────────────────────┐
│ ┌────────────────────────────┐ ┌─┐ │
│ │ 🙂  输入消息…           ＋ │ │🎤│ │
│ └────────────────────────────┘ └─┘ │
└────────────────────────────────────┘
```

有草稿时：

```text
┌────────────────────────────────────┐
│ ┌────────────────────────────┐ ┌─┐ │
│ │ 🙂  明天上午可以…       ＋ │ │➤│ │
│ └────────────────────────────┘ └─┘ │
└────────────────────────────────────┘
```

规则：

- 输入胶囊包含 emoji、编辑器和附件；
- 外侧主按钮为空草稿时为录音，有草稿时为发送；
- 录音属于需要学习的手势，首次触达要显示“按住说话”提示；
- 所有触控目标达到推荐的 44px；
- 输入框一到多行增长，达到上限后内部滚动；
- 附件菜单按用户任务命名，平台不支持的能力不出现；
- 上传/发送中不应冻结整个输入区，除非后端不允许并发发送；
- 软键盘打开后输入区与键盘贴合，时间线底部保持可见。

### 6.4 输入区扩展状态

| 状态 | 结构规则 |
| --- | --- |
| emoji 面板 | 位于输入区上方；Compact 充分利用宽度；关闭后恢复编辑器焦点 |
| 附件菜单 | 优先底部面板或锚定菜单；不得被键盘/安全区裁切 |
| 链接预览 | 输入区上方紧凑卡片，可关闭；加载失败降级为 URL |
| 录音中 | 输入内容让位于录音时长与取消提示；主按钮状态明显 |
| 录音取消区 | 手势进入取消阈值后同时使用颜色、图标和文字反馈 |
| 权限失败 | 输入区附近说明原因，并提供打开系统设置的恢复动作 |
| 上传中 | 对应待发送消息显示进度；输入区继续可用 |

## 7. Medium：主从布局

Medium 不再完全复用 Compact 的全屏会话切换，而是使用双栏主从结构：

```text
┌──────────────────┬────────────────────────────────────┐
│ SOMS      ＋ 头像│ (头像) 林晓                 📞  ⋯  │
├──────────────────┼────────────────────────────────────┤
│ 🔍 搜索           │                                    │
│ [全部][未读]      │             消息时间线              │
│                  │                                    │
│ 会话 1            │                                    │
│ 会话 2            │                                    │
│ 会话 3            ├────────────────────────────────────┤
│                  │ 🙂  输入消息…             ＋   🎤  │
└──────────────────┴────────────────────────────────────┘
```

结构规则：

- 左侧会话栏建议宽度 300–360px，并根据可用宽度自适应；
- 不显示 Expanded 的独立图标导航栏；
- 账户和新建入口保留在会话栏头部；
- 右侧无选中会话时显示聊天空状态；
- 联系人/群资料和设置以覆盖右侧内容的抽屉或全屏层呈现，不压缩聊天到不可用宽度；
- 系统返回优先关闭详情抽屉，再清除当前聊天选择；
- 768px 竖屏是否保持双栏，需使用真实内容验证；若聊天宽度不足，可退化为 Compact；
- 平板触控仍使用 44px 目标，不因为双栏而套用桌面紧凑控件。

## 8. Expanded：桌面布局

### 8.1 默认结构

```text
┌──────┬──────────────────────┬────────────────────────────────────┐
│ 头像 │ 会话            ＋   │ (头像) 林晓          搜索  📞  ⋯  │
│      ├──────────────────────┼────────────────────────────────────┤
│ 好友 │ 🔍 搜索              │                                    │
│ 群组 │ [全部][工作][家人]    │             消息时间线              │
│ 文件 │                      │                                    │
│      │ 会话 1               │                                    │
│      │ 会话 2               │                                    │
│      │ 会话 3               │                                    │
│      │                      ├────────────────────────────────────┤
│ 设置 │                      │ 🙂  输入消息…             ＋   🎤  │
│ 主题 │                      │                                    │
└──────┴──────────────────────┴────────────────────────────────────┘
```

### 8.2 图标导航

- 继续使用约 64–72px 的图标导航栏；
- 只放一级、稳定、跨上下文的入口；
- 头像、好友请求、群组/新建、文件夹、设置和主题的具体组合需避免重复；
- “新建群聊”属于新建任务，更适合会话栏的 `＋` 菜单，不一定永久占用一级导航；
- 每个图标提供本地化 accessible name 和 tooltip；
- 当前一级区域必须有 selected 状态；
- 未处理好友请求显示数字或可理解角标；
- 键盘可依次导航，focus ring 不被圆形容器裁切。

### 8.3 会话栏

- 默认宽度建议 320px；
- 最小约 280px，最大约 420px，具体通过长名称和窗口缩放验证；
- 分栏拖动条使用 separator 语义，支持方向键调整和双击/快捷操作重置；
- 会话栏顶部拥有明确标题和新建入口；
- 搜索与文件夹标签位于标题下；
- 滚动只发生在会话列表区域，标题、搜索和标签保持可用；
- 窗口过窄进入 Medium，而不是把聊天区压缩到不可用。

### 8.4 聊天与详情

- 聊天区占据剩余空间，正文内容可使用合理最大宽度，避免大屏上消息跨度过大；
- 资料详情以右侧覆盖抽屉呈现，默认宽约 360–400px；
- 抽屉开启时使用轻遮罩，点击遮罩、Escape 或关闭按钮均可关闭；
- 抽屉不永久挤压聊天区；
- 无选中会话时显示克制的产品空状态，不显示完整输入区。

## 9. 聊天空状态

### 9.1 Medium/Expanded 未选择会话

```text
┌────────────────────────────────────┐
│                                    │
│             [品牌图形]              │
│                                    │
│          选择一段会话开始聊天        │
│    或使用左侧的新建按钮联系其他人     │
│                                    │
│             [ 新建聊天 ]            │  可选
│                                    │
└────────────────────────────────────┘
```

规则：

- 如果左栏的新建按钮已经非常明确，空状态 CTA 可以省略；
- 不渲染可编辑输入区，避免用户输入后才发现没有目标会话；
- 不使用大面积渐变或强品牌插画填满聊天区。

### 9.2 已选中但没有历史消息

- 保留正常聊天头部和输入区；
- 时间线中显示轻量关系提示或群聊欢迎信息；
- 主操作仍然是输入消息，不额外放置竞争 CTA；
- 可以提供少量快捷建议，但第一批不实现，以免增加产品规则。

## 10. 连接与更新状态位置

### 10.1 连接状态

| 状态 | 建议位置 | 行为 |
| --- | --- | --- |
| 正常在线 | 默认不显示 | 不持续占用空间 |
| 正在连接 | 全局顶层紧凑状态条/chip | 延迟出现，避免短抖动 |
| 重连中 | 同一位置 | 显示用户文案，可进入详情 |
| 离线 | 同一位置，警告语义 | 明确仍可查看缓存，发送将等待或失败 |
| 恢复成功 | 原位置短暂成功反馈 | 自动收起，不要求用户关闭 |

连接状态不能遮挡首页新建、聊天更多和系统状态栏。

### 10.2 更新提示

- 不与连接状态同时争夺顶栏相同位置；
- 非强制更新使用可延后的低干扰提示；
- 强制或壳版本不兼容使用阻断页面/弹窗，并说明明确动作；
- Android 更新、桌面更新和 Web Service Worker 更新使用同一用户语言，不暴露实现差异。

## 11. 导航和返回规则

### 11.1 Compact

```text
首页 → 聊天 → 联系人/群资料 → 二级资料操作
```

返回顺序：

1. 关闭临时菜单、emoji、附件面板；
2. 关闭弹窗或媒体查看器；
3. 从二级资料操作返回资料；
4. 从资料返回聊天；
5. 从聊天返回首页；
6. 首页再次返回交给系统。

### 11.2 Medium/Expanded

- 选择会话不替换整个页面；
- 关闭详情返回聊天，而不是清除当前会话；
- Escape 只关闭最上层临时 UI；
- 浏览器深链接 `/chat/:threadId` 可恢复对应会话；
- 搜索、文件夹和列表滚动位置属于当前工作区状态，不应因打开详情丢失。

## 12. 键盘和焦点顺序

### Expanded 推荐顺序

```text
图标导航
  → 会话栏标题操作
  → 搜索
  → 文件夹标签
  → 会话列表
  → 聊天头部
  → 消息时间线
  → 输入区
```

规则：

- 不要求 Tab 穿过时间线中的每条普通消息；
- 消息中的链接、失败重试、文件和媒体等真实操作可进入 Tab 顺序；
- 会话列表可采用 roving tabindex，减少 100+ 行带来的 Tab 成本；
- 打开聊天后，鼠标/触控操作不强制移动到输入框；
- 使用键盘打开会话时，将焦点置于聊天标题或按明确产品规则进入输入区；
- 关闭菜单、抽屉、弹窗后焦点返回原触发器。
