# SOMS C 端页面与状态验收矩阵

状态：Draft v0.1  
依赖：[SOMS C 端 UI 改造原则](./consumer-ui-redesign-principles.md)  
范围：`web/` 及其 Tauri 内嵌运行形态

## 1. 文档目的

本文档把 C 端 UI 改造目标转换为可重复执行的验收场景。它用于：

- 建立改造前后的截图和行为基线；
- 避免只验证理想数据与单一设备；
- 明确每个页面必须具备的 loading、empty、error 和 ready 状态；
- 约束 Compact、Medium、Expanded 三档布局；
- 定义每次提交的冒烟检查和阶段完成时的全量回归；
- 为后续视觉回归测试、组件测试和真实设备测试提供场景编号。

本矩阵检查界面体验，不替代现有单元测试、后端 E2E 测试或协议测试。

## 2. 验收级别

| 级别 | 含义 | 执行时机 |
| --- | --- | --- |
| P0 | 核心链路或高风险平台行为 | 每个相关提交 |
| P1 | 高频功能和主要异常状态 | 每个功能批次完成时 |
| P2 | 低频功能、极端数据和增强体验 | 阶段回归或发布前 |

验收结果使用以下状态：

- `PASS`：视觉和行为均符合预期；
- `FAIL`：存在明确退化或不符合完成定义；
- `BLOCKED`：缺少环境、权限或测试数据；
- `N/A`：该平台或配置不适用。

`BLOCKED` 不能视为通过，必须记录阻塞条件和补测计划。

### 3.3 主题与语言

| 轴 | 必测值 |
| --- | --- |
| 主题 | 浅色、深色、跟随系统切换 |
| 语言 | 简体中文、英文 |
| 字体缩放 | 100%、系统大字体/浏览器 200% 文本 |
| 动效偏好 | 默认、`prefers-reduced-motion: reduce` |

## 4. 标准测试数据

为减少不同开发者截图和判断的差异，准备以下固定数据：

### 4.1 用户与会话

- 当前用户：有头像、有昵称、已设置密码；
- 普通联系人：短中文名、在线；
- 长名称联系人：中英文混合且超过一行；
- 联邦联系人：带域名标识；
- 已拉黑或关系异常联系人；
- 普通群、长群名群、联邦群；
- 空会话账号；
- 20 条普通会话；
- 100+ 条会话，用于滚动和搜索性能；
- 置顶、静音、未读、草稿、发送失败等不同状态会话。

### 4.2 消息

- 短文本、长文本、多段文本、emoji-only；
- 中英文、URL、超长连续字符串；
- 自己和他人的连续消息组；
- 图片单张、2–9 张相册、超宽/超高图片；
- 视频、音频、普通文件和超长文件名；
- 链接预览成功、无图片和加载失败；
- 群邀请消息；
- 通话记录；
- 正在发送、发送成功、发送失败、重试中；
- 历史空白、少量历史和长历史；
- 同一天、跨天和跨年份消息。

### 4.3 权限与网络

- 正常网络；
- 高延迟；
- 断网；
- 连接中断后自动恢复；
- 服务器不可达；
- 登录失效；
- 相机、麦克风、通知权限的首次请求、允许、拒绝和永久拒绝；
- 上传过程中断网；
- Tauri 原生命令不可用或版本不兼容。

## 15. 全局视觉一致性检查

以下检查适用于每一个完成改造的页面：

- 页面只有一个清晰的视觉标题和一个主要动作；
- 相同语义使用相同颜色、图标、文字和反馈位置；
- 没有系统 emoji 充当正式操作图标；
- 没有无依据新增的颜色、圆角、阴影、字号或动效时长；
- hover、pressed、focus-visible、selected 和 disabled 可区分；
- 可点击区域与视觉区域一致，不存在大面积“隐形点击区”；
- 内容在浅色和深色主题下均有合理对比度；
- 长名称、域名、错误文案和英文文本不会撑破布局；
- 加载完成、列表更新和页面切换没有明显布局跳动；
- 触控目标和相邻操作间距适合真实设备；
- 危险操作不会与主要安全操作拥有相同视觉权重；
- 所有正式文案和辅助文本已国际化。

## 17. 第一批改造验收门槛

首页、会话列表、聊天头部、消息区和输入区第一批改造完成时，至少满足：

- 所有对应 P0 场景 `PASS`；
- P1 场景无影响主任务的 `FAIL`；
- VP-C1、VP-C2、VP-C3、VP-M1、VP-M2、VP-E1、VP-E2 均有基线截图；
- Android 真机完成冷启动、系统返回、软键盘、横屏、录音和附件检查；
- 浅色中文、深色中文、浅色英文至少各完成一次核心链路；
- 键盘可以从桌面导航进入会话、打开聊天、操作头部和发送消息；
- `prefers-reduced-motion` 下没有阻碍任务的动画；
- Angular 测试和生产构建通过；
- 没有新增硬编码英文辅助文本；
- 已知问题具有场景编号、截图、影响范围和后续处理计划。

## 18. 截图与问题记录约定

建议使用以下文件名，便于后续自动比较：

```text
<scene-id>__<platform>__<viewport>__<theme>__<lang>__<state>.png
```

示例：

```text
HOME-001__PF-A__VP-C2__dark__zh-CN__ready.png
MSG-005__PF-W__VP-E2__light__en__failed.png
```

每个失败项至少记录：

- 场景编号；
- 实际平台、系统版本和视口；
- 测试数据或前置状态；
- 预期结果；
- 实际结果；
- 截图或录屏；
- 是否为改造前已存在；
- 严重程度和建议归属组件。

## 19. 后续自动化方向

本矩阵先作为人工验收基线，后续逐步自动化：

1. 为稳定的登录、首页空状态、会话列表、设置等页面增加截图 fixture；
2. 使用浏览器自动化生成 VP-C1、VP-M1、VP-E2 的浅色/深色截图；
3. 使用 axe 检查 accessible name、角色、焦点和基础对比度问题；
4. 为系统返回、软键盘、权限和原生透明层保留 Android 真机测试；
5. 将 P0 Web 场景和生产构建加入合并前检查；
6. 将截图差异与本矩阵场景编号关联，避免无上下文更新基线。
